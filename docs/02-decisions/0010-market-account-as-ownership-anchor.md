# ADR 0010 — 소유의 근거는 마켓이 발급한 토큰이다

## 상태

채택. 2026-08-02.

초판(같은 날)은 "마켓 계정 해시가 같으면 같은 사람"을 근거로 삼았다.
**그 전제가 틀렸다.** 아래 "정정" 절에 남긴다.

## 맥락

lizard-tycoon은 전원 Firebase 익명 인증이다. 앱을 지우면 uid가 새로
생기고 `platform_user_id`도 새로 생긴다. 구글·애플 계정은 그대로인데
우리 원장의 소유자만 바뀐다.

실기기에서 그대로 막혔다.

```
Play 구매 시트   → "You already own this item"   (소유 중이라 못 산다)
플랫폼 원장      → 소유권 없음                    (지급된 적 없다)
복원 시 서버     → 409 account_binding_mismatch   (계정 참조가 다르다)
```

살 수도 되찾을 수도 없다. 재설치한 모든 유저가 산 상품을 잃는다.

## 정정 — 마켓 계정 식별자는 존재하지 않는다

초판은 `processed_orders.platformAccountIdHash`를 "마켓이 알려준 계정
식별자"로 보고 그것이 같으면 이전을 허용했다. 실제 값은 다르다.

```go
PlatformAccountID: resp.ObfuscatedExternalAccountID   // Play가 돌려주는 값
GoogleAccountID(puid) = HMAC(key, "google:" + puid)   // 우리가 만든 값
```

**우리가 `platform_user_id`로 만든 HMAC이다.** Apple의 `appAccountToken`도
같다. uid가 바뀌면 이 값도 반드시 바뀌므로, "같은 계정인지"를 이것으로
판정할 수 없다.

Play도 Apple도 **안정적인 마켓 계정 식별자를 주지 않는다.** 그런 필드는
없다.

## 결정

**소유의 근거를 마켓이 이 계정에 발급한 토큰으로 삼는다.**

- Play `queryPurchases`는 **현재 로그인된 구글 계정이 가진 구매만** 준다
- Apple은 **Apple ID에 묶인 거래만** 준다
- 우리는 그 토큰을 마켓 API로 다시 검증한 뒤에야 지급 판단에 들어간다

토큰을 손에 넣었다는 사실 자체가 마켓이 내린 소유 판정이다. 별도
식별자가 필요하지 않다.

따라서

- **계정 바인딩 불일치는 지급을 막지 않는다.** 부정 신호로 감사 원장에
  `iap.binding_mismatch`로 남긴다
- **원장에 다른 소유자가 있어도 새 소유자로 이전한다.** `iap.transferred`로
  남긴다

## 근거

**Google은 이 필드를 소유권 판정 수단으로 두지 않는다.** 문서는
`obfuscatedAccountId`를 "optional but recommended"로 두고 용도를 **부정
탐지와 귀속**으로 설명한다. 불일치를 거부 사유로 쓰라는 요구는 없다.
오히려 *"reconciling purchases where your app may have lost context about
which user a purchase is for"* — 앱이 사용자 맥락을 잃는 상황을 정상
시나리오로 전제한다.

**Apple은 복원을 의무화한다.** 심사 지침 3.1.1은 비소비성 상품에 재설치·
기기 변경 후 복원 수단 제공을 요구하고, 그 동작을 "Apple ID에 묶인
거래를 가져와 entitlement를 다시 지급"으로 규정한다. 거부하는 구현은
리젝 사유다.

**대안을 검토했다.**

| 안 | 판단 |
|---|---|
| 신규/복원을 요청 필드로 구분 | 클라이언트가 그 값을 정한다. 위조하면 같아지므로 실질 방어력이 없다 |
| 계정 연동(이메일·소셜) | 옳지만 연동하지 않은 유저는 여전히 잃는다. 익명 전용 앱에는 지금 답이 아니다. 후속 과제 |
| 소비성 재화(보석)로 전환 | **문제를 키운다.** 소비성은 마켓 복원 경로가 없어 재설치하면 되찾을 근거가 어디에도 없다 |

## 감수하는 위험

**남의 `purchaseToken`을 손에 넣으면 그 상품을 가져갈 수 있다.**

바인딩은 이 공격을 막던 장치였다. 없애면 방어가 준다. 다만

- 토큰은 로그·커밋에 남기지 않는다 (조직 원칙)
- TLS로만 오간다
- 이전은 `iap.transferred`로 감사 원장에 남아 사후 추적이 된다
- 마켓 검증을 통과해야 하므로 만료·환불된 토큰은 쓸 수 없다

근본 해결은 계정 연동이다. 익명 uid에 소유권을 매다는 구조 자체의
한계이고, 유료 재화를 도입한다면 그것이 선행 조건이다.

## 강제하는 규칙

**이전은 이동이지 복제가 아니다.** 한 구매가 두 `platform_user`에서
동시에 활성이면 원장이 깨진다. 이전 소유자의 source를 걷어내고
projection을 다시 쓰는 것과 새 소유자 지급을 **한 트랜잭션**에서 한다.

**되돌릴 수 없는 조작은 따로 남긴다.** `iap.transferred`를 `iap.granted`에
섞으면 "이 유저가 언제 무엇을 잃었나"를 찾을 수 없다. BigQuery 감사
projection이 실패해도 이전 소유자를 복구할 수 있도록, 토큰·provider 주문
식별자·마켓 계정 참조를 제외한 최소 증거를 append-only
`iap_ownership_transfers`에 소유권 변경과 같은 트랜잭션으로 영구 저장한다.

## 결과

재설치한 유저가 복원으로 구매를 되찾는다. Apple 3.1.1 요구를 만족한다.

AIT는 이 경로에 해당하지 않는다. 계정 바인딩이 면제이고 `aitUserKey`
claim 발급 경로가 미구현이라 별도로 다룬다.
