# ADR 0005: 플랫폼은 PII를 저장하지 않는다

## Status

Accepted

## Context

플랫폼은 여러 앱의 사용자 데이터를 한곳에 모은다. 개인정보를 어디까지 다룰지 정해야 한다.

법적 환경:

- **개인정보보호법은 사업자 규모와 무관하게 적용된다.** 1인 기업도 예외가 없다
- **만 14세 미만 아동은 법정대리인 동의가 필요하다.** 게임 앱에서 실제 리스크다
- **Google Play Data safety 허위 신고는 앱 정지 사유다**

현재 조직 앱은 **대부분 익명 인증**이라 이메일이 존재하지도 않는다.

## Decision

**플랫폼은 개인정보를 저장하지 않는다.**

플랫폼이 갖는 식별자는 자체 생성 `platform_user_id`(ULID)와 `(app_id, firebase_uid)` 매핑뿐이다. 이메일·이름·전화번호는 **각 앱의 Firebase Auth에만** 남는다.

**마켓 계정 식별자도 원문을 저장하지 않고 sha256만** 저장한다. lizard-tycoon의 기존 규칙을 승계한 것이다.

### CS는 support code로 한다

```
앱 설정 화면 → [내 지원 코드 복사] → LT-8F3K2Q9M
유저 문의 시 코드 첨부 → 백오피스에서 코드로 검색
```

이메일 검색은 애초에 성립하지 않는다. (a) 플랫폼이 이메일을 받지 않고 (b) Firestore는 부분 검색이 불가하다.

## Consequences

- `firebase_uid`가 가명정보에 해당하므로 **규제 완전 밖은 아니다.** 다만 이메일·이름을 보관하는 것과는 리스크 차원이 다르고, **확인해야 할 범위 자체가 작아진다**
- **이벤트 파라미터 PII 키 blocklist를 SDK에 넣는다.** `email`, `phone`, `name`, `address`, `birth` 등을 drop한다. 개발자가 무심코 `log_event("login", {email})` 하는 게 실제로 가장 흔한 사고라 conformance 벡터로 CI에서 강제한다
- **`DELETE /v1/users/me`를 1단계에 넣는다.** PII를 갖지 않더라도 삭제 경로는 있어야 한다. 앱에서 계정을 지웠는데 플랫폼에 원장이 남아 있으면 그 자체가 문제다
- orphan `platform_user`는 Firestore TTL로 `lastSeenAt + 400일`에 자동 삭제한다
- **파일럿 앱의 Data safety / App Privacy 신고를 갱신해야 한다.** "기기 ID", "앱 활동"이 추가된다
- 개인정보 처리방침에 "플랫폼 서버로 전송"을 반영한다. `starter-template-*` 템플릿에도
- **로그에 토큰·영수증·마켓 계정 식별자 원문을 남기지 않는다**

### 2단계 — 지금 만들지 않는다

계정 연동으로 이메일이 정말 필요해지면 **저장하지 않는 방식**을 쓴다. 플랫폼이 각 앱 프로젝트에 `roles/firebaseauth.viewer`를 갖고, CS 조회 **시점에만** Admin SDK로 가져와 화면에 표시만 하고 저장·로깅하지 않는다. IAM 권한이 늘어나므로 1단계에서 제외한다.

## Alternatives Considered

- **이메일을 저장해 검색 가능하게** — 검색 편의를 얻는 대신 개인정보 처리자 의무 범위가 크게 늘어난다. 게다가 Firestore는 부분 검색이 불가해 **편의도 절반만 얻는다**
- **마켓 계정 식별자 원문 저장** — 디버깅이 편해지지만 유출 시 피해가 크다. 해시로도 동일성 비교는 가능하다
