# 크리스털 구매 지급 알림 누락 보강

일반 IAP는 지급과 같은 Firestore transaction에서 `iap.granted`를 기록하지만 크리스털 5종은 `grantEconomyPurchase`로 분기한 뒤 알림을 만들지 않는다. 2026-10-20 KST 문라이트 혼 리자드 실구매는 Discord 원문까지 확인됐고, 같은 날 크리스털 스타터 실구매는 지급 원장만 있고 건별 이벤트가 없다. 사용자의 2026-10-25 대화 지시 「보강할 수 있어?」에 따라 확인된 누락을 기존 ADR 0017의 지급 알림 계약에 맞춘다.

새 크리스털 지급 확정 → 같은 transaction에 기존 `iap.granted` 저장 → 기존 발신 대기열 처리 → Backoffice → Discord 결제 채널. 재화 적립이 실제 적용된 경우에만 알리며 같은 주문 재처리와 환불 후 재검증은 새 지급 알림을 만들지 않는다. 반복 구매 가능한 상품은 서로 다른 주문마다 한 번씩 알린다. `platform`, `entitlementId`, 검증된 경우의 `isTestPurchase`만 보내고 미확인 테스트 여부는 생략한다. 사용자 ID, 주문 원문과 금액은 추가하지 않는다.

변경은 기존 크리스털 지급 함수와 회귀 테스트에 한정한다. 상품, 가격, 지급량, API 계약, 클라이언트, GA4, 자격증명과 과거 거래는 바꾸지 않는다. 과거 누락 알림의 소급 전송은 포함하지 않는다. 새 계층이나 전송 경로를 추가하지 않고 일반 상품과 같은 이벤트 형식을 사용한다. 알림 저장이 실패하면 지급과 주문 기록도 함께 롤백되어 재시도로 전체를 처리한다.

L1 개발 환경 검증으로 Firestore 에뮬레이터에서 5개 상품, Google Play와 App Store의 실제, 테스트, 미확인 구분, 동일 주문 재시도, 동시 요청, 별도 주문 재구매, 환불 후 재검증과 알림 기록 실패 시 롤백을 확인한다. 기존 Go 검사와 서비스 실행 회귀도 수행한다. UI와 기기 검수는 해당 없다. 운영 구매나 테스트 메시지는 보내지 않는다. 이번 지시는 구현, 검증과 PR 병합 범위로 기록하고 운영 배포의 GitHub environment 승인은 별도 확인한다. Version Impact: patch.
